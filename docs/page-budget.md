已发布基线 = `content/published-log.tsv` 按追加顺序最后一条有效发布记录的已部署提交；所有非空行都必须有效，遇到无效行即停止检查，不跳过错误行。只有日志为空或缺失时才打印警告并回退到固定初始值 `ecd433cd86c7d06be7bed0ca5522f9e46841fefa`（2026-11-01 确认的线上提交，当时的 `origin/main`）。基线不随 `main` 或 `origin/main` 移动，本地 `published` 标签缺失或与日志不一致均不影响基线。`publish.sh` 仅在部署成功后向日志追加一行「UTC 时间<TAB>已部署提交哈希」；发布日志与成功的 IndexNow 记录一起提交，然后推送 `origin/main`，记录提交本身不作为已部署基线。IndexNow 失败仍提交成功发布的日志；日志提交失败则停止推送。`--check` 不写发布日志，也不创建或移动标签。日志初始行使用上述初始已发布提交及其提交时间。

本次新增 = 当前构建 sitemap − 已发布基线 sitemap。正文变化也只与这个已发布基线比较，合并进 main 不能让尚未发布的新增或修改归零。近 7 天滚动新增 = 当前构建 sitemap − 滚动已发布基线 sitemap。滚动基线取 `content/published-log.tsv` 中发布时间 ≤ 检查时刻减 7 天的最新一次发布提交；没有这样的记录时用最早发布，记录为空或文件缺失时用固定初始已发布提交。只按成功发布时间选择，普通提交不能成为滚动基线；未发布的新页无论提交多久都计入滚动新增。滚动基线只用于网址预算，不用于正文比较。翻译版本独立计数；发布记录无效或本地缺少所选提交及 sitemap 时报错，不联网补取。

本次新增为 0 时，数量闸门通过，滚动新增数只作提醒。本次新增大于 0 且滚动新增大于 3 时失败，除非具备下述例外。独有率仍独立检查，正文变化的存量页不会因本次没有新增网址而豁免。

IndexNow 在 `tools/indexnow-state.json` 逐页保存 lastmod、description、正文签名和签名版本，正文归一化复用预算脚本。前三项任一变化即列入推送；签名只在版本一致时比较。旧记录缺少签名或签名版本升级时，首次仅建立新签名基线，不因迁移本身推送，lastmod 或 description 的真实变化仍照常列入。没有待推送变化时，普通运行可保存迁移基线；有待推送变化时，只有推送成功才保存；失败和 `--dry-run` 都不写状态。修改签名归一化规则时须递增 `BODY_SIGNATURE_VERSION`。
